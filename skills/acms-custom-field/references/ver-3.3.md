# Ver. 3.3 でのカスタムフィールドの変化

このファイルは、作業対象の a-blog cms が Ver. 3.3 以上のときだけ読む。Ver. 3.2 のサイトには当てはめない。Ver. 3.3.0-alpha.1 のソースで確かめた内容で、正式版で変わることがある。

## 入力欄を HTML を書かずに定義できる

Ver. 3.3 では、管理画面の「フィールド定義」と、テーマの `admin/field-definitions/<対象>.json` で入力欄を定義できる。設計・作成・変更は acms-field-definition を使う。

| 状況 | 選ぶ方法 |
|---|---|
| 新しく入力欄を作る | フィールド定義（acms-field-definition）を第一に検討する。入力チェック・公開時に必須・条件付き表示・参照型が HTML なしで使える |
| 既存の `field.html` の入力欄を直す・足す | そのまま `field.html` で直してよい。移行は必須ではない |
| 定義の型にない入力欄（独自の UI） | `field.html`、または独自の型（acms-field-definition） |

- `field.html` と定義は同時に使える。**同じキーが両方にあれば `field.html` が優先**され、定義の入力欄は出ない。
- 定義の値は従来のカスタムフィールドとして保存されるので、出力の記法（このスキルの「出力する」）は変わらない。
- テーマで `admin/entry/edit.html` などの編集画面を上書きしていると、定義の入力欄が出ない（acms-field-definition の「従来の field.html との関係」）。

## field.html に書いてはいけないもの

Ver. 3.3 の編集画面は、定義の「公開時に必須」をサーバー側で強制する。`field.html` に自分で `:validator#editor_required` の hidden を書かない。強制の対象外のときに保存できなくなるため。

## 参照型の出力

フィールド定義の参照型（エントリー・カテゴリー・ユーザーを指す項目）は、`{キー@title}`・`{キー@url}` などの値が補われる。出力は acms-field-definition の references/field-types.md の「参照型」を読む。

## カスタムフィールドメーカー

カスタムフィールドメーカーの生成コードを、フィールド定義のテンプレート型にそのまま貼らない（現在の値が空で描画され、保存すると既存の値を空で上書きする）。メーカーの生成コードは従来どおり `field.html` に使う。
