# モジュール ID の仕組み

モジュール ID を作る・付ける・名前を決めるとき、「モジュールが出ない」「設定が効かない」「別のページと同じ内容が出る」ときに読む。
作り方の画面説明と各項目の意味は公式ドキュメント（<https://developer.a-blogcms.jp/document/moduleid/setting.html>、<https://developer.a-blogcms.jp/document/moduleid/argument.html>）を見る。

## 基本

- モジュール ID は管理画面（モジュール ID 管理）で作る、ブログに属する DB の設定。テンプレートに書くだけでは作られない。
  - テンプレートでは、標準は `<!-- BEGIN_MODULE Entry_Summary id="news" -->`、Twig は `module('V2_Entry_Summary', 'news')` の第2引数で指定する。
  - 別の環境へは、モジュール ID 管理のエクスポート・インポート（またはブログ全体の設定の書き出し・読み込み）で持ち込む。
- ID は「モジュール名と ID の組」で探される。`Entry_Summary` 用の ID `news` を、テンプレートの `Entry_Headline id="news"` や `V2_Entry_Summary` の `news` から使うことはできない。
- ID が持つもの: 表示設定（件数・並び順・表示項目など）、表示する対象と、項目ごとの「〜のURLコンテキストを優先する」の設定、キャッシュ時間、モジュールフィールド（`Module_Field` で表示する）、グローバル（子ブログへの公開）。

## ID を付けないとき

- モジュールは動く。表示設定は、そのブログのコンフィグ（管理画面のモジュールごとの設定）が使われる。同じ種類の ID なしモジュールは、すべて同じ設定を共有する。
- 対象は、テンプレートの `ctx` / 第3引数と URL コンテキストだけで決まる（下の「優先関係」）。
- モジュールキャッシュは使えない。`Module_Field` は何も出さない。
- 判断: ページごとに設定を変えたい、運用者に件数や対象を変えさせたい、キャッシュしたいなら ID を付ける。どこでも同じ設定でよく、対象をテンプレートで固定できるなら付けなくてよい。

## ID が見つからないときの挙動

テンプレートに書いた ID が見つからなくても、エラーもログも出ない。ID が無いものとして（上の「ID を付けないとき」と同じく）動く。結果として、

- `Navigation`・`Links`・`Media_Banner`・`Module_Field` のように ID の設定に中身を持つモジュールは、何も出ない（ブログのコンフィグ側にも設定があれば、その内容が出る）。
- `Entry_Summary` などは表示されるが、件数・並び順・絞り込みが ID の設定と違う。

見つからない条件:

1. 管理画面にまだ作っていない（テーマを複製・継承したとき、別の環境から持ってきたときに起きやすい）。
2. 綴りが違う。または、ID のモジュール名とテンプレートのモジュール名が違う（非推奨モジュールを代替へ書き換えた、標準テンプレートを Twig に移した、など）。
3. ID のステータスが有効になっていない。
4. 表示中のブログから使えない場所にある（下の「ブログをまたぐスコープ」）。

ほかに、ID の設定（標準テンプレートでは `ctx` も）で特定のエントリーを指定していて、そのエントリーが非公開・公開期間外で閲覧者に権限がないとき、または ID の属するブログの配下にないエントリーのとき、モジュールは何も出さない。こちらは監査ログに通知が残る。

確かめ方:

- 管理画面のモジュール ID 一覧で、表示中のブログ（または「グローバル」にした親ブログ）に、同じモジュール名・同じ ID・有効なものがあるかを見る。
- 管理者でログインして編集ボタン（下記）を見る。標準テンプレートでは、ID が見つかったときは「編集する」、見つからないときは「（モジュール名）を編集する」と出る。後者はブログのコンフィグの編集画面を開く。

利用者に「出るはずのものが出ない」と言われたら、テンプレートや CSS を直す前に、まず ID の実在を確かめてもらう。

## ブログをまたぐスコープ

| ID を作った場所 | 「グローバル」のチェック | 表示中のブログから使えるか |
|---|---|---|
| 表示中のブログ | どちらでも | 使える |
| 祖先（親・その上）のブログ | あり | 使える。設定と編集ボタンは ID を作ったブログのもの |
| 祖先のブログ | なし | 使えない |
| 兄弟・子孫のブログ | どちらでも | 使えない |

ID の名前の重複は次のように制限される（保存時に「モジュール ID が重複しています」になる）。

- 同じブログの中では、モジュール名が違っても同じ ID は作れない。
- 祖先のブログに同じ名前のグローバルな ID があると、子孫のブログでは作れない。
- グローバルにする ID と同じ名前の ID が子孫のブログにあると、グローバルにできない。

この結果、子ブログごとに設定を変えたいかで作り方が決まる。

| やりたいこと | 作り方 |
|---|---|
| すべての子ブログで同じ設定を使う | 親ブログに作り、グローバルにする。子ブログでは同じ名前を作れない |
| 同じテンプレートのまま、子ブログごとに設定を変える | 親ではグローバルにせず、各ブログに同じ名前の ID を作る |

## URL コンテキストと ctx の優先関係

項目（`cid`・`eid`・`uid`・`keyword`・`tag`・`field`・`start`・`end`・`page`・`order`）ごとに、次の順で決まる。

| 順 | 判断 |
|---|---|
| 1 | その項目の「〜のURLコンテキストを優先する」（引数のチェック）が有効で、URL に値があれば、URL の値 |
| 2 | そうでなければ、モジュール ID の設定値 |
| 3 | ID に値がなければ、テンプレートの指定（標準の `ctx="cid/3"`、Twig の第3引数 `{ cid: 3 }`） |
| 4 | どれもなければ指定なし（引数のチェックが無効なら、URL に値があっても使わない） |

- `bid` は引数のチェックの対象ではない。ID の設定値 → テンプレートの指定 → 表示中のブログ、の順。
- ID がないときの引数のチェックの既定値は、モジュールのクラスごとに決まっている。`Entry_Body` は URL に従い、`Entry_Summary` は従わない（ページ送りやカテゴリーに追従させるなら ID を作って引数をチェックする）。既定値の表: <https://developer.a-blogcms.jp/document/moduleid/entry-2730.html>
- よくある誤り: ID に `cid` を設定したまま、テンプレートの `ctx` でカテゴリーを変えようとする（ID の設定値が勝つので変わらない）。
- Twig だけの注意: 第3引数の `limit` は ID の件数設定より優先される。運用者に件数を任せるなら `limit` を渡さない。

## キャッシュ

- ID の「キャッシュ」に分を入れると、ログインしていない閲覧者に対して、モジュールの結果がその時間だけ再利用される。ID を付けていないモジュールでは使えない。
- キャッシュのキーはモジュール名と ID だけで、URL・`ctx`・ブログ・テンプレートを含まない。最初に作られた結果が、有効期限まで他のページ・他のテンプレートでも使われる（標準は組み立て済みの HTML、Twig は戻り値のデータ）。
  - 向く: グローバルナビゲーション、フッターのリンク集など、どのページでも同じ内容のもの。
  - 向かない: 引数のチェックが有効なもの、ページごとに `ctx` / 第3引数を変えるもの、同じ ID を違うマークアップのテンプレートで使うもの（標準）、子ブログごとに同じ名前の ID を作っているもの（ブログ間で結果が混ざる）。
- エントリーを更新してもモジュールキャッシュは消えない。ID の設定を保存したときと、有効期限が切れたときに入れ替わる。ただし V2 モジュールのキャッシュは ID を保存しても消えない（Ver. 3.2.38 で確認）。すぐ反映させたいときは、管理画面のキャッシュクリアでモジュールのキャッシュを対象にする。
- ページ全体のキャッシュとは別の仕組み。公式の説明: <https://developer.a-blogcms.jp/document/moduleid/cache.html>

## 編集ボタン

管理者でログインしているとき、モジュールの横に設定画面へのボタンを出せる（プレビュー中は出ない）。

- 標準テンプレート: `BEGIN_MODULE` の内側に `@include("/admin/module/setting.html")` を書く。モジュールの外に書くと ID の情報が入らない。
- Twig: `{{ include('/admin/module/setting.twig', { moduleInfo: 変数.moduleInfo }) }}`。V2 モジュールの戻り値の `moduleInfo` は管理者のときだけ入る。
- ID が見つかったときはモジュール ID の編集を、見つからないときは（ID なしと同じく）ブログのコンフィグの編集を開く。

## ID の名前の付け方（a-blog cms の挙動に理由があるものだけ）

- 何をどこに出すかが分かる名前にする。理由: 同じブログの中ではモジュールの種類をまたいで ID が一意で、グローバルにした親の ID とも重複できない。`list` や `nav` のような汎用の名前はすぐ衝突する。
- 管理画面の説明どおり半角英数字にする（区切りに `_` を使うのは公式の例と同じ）。空白・引用符・`=` は標準テンプレートの `id="..."` から正しく取り出せない。64 文字以内。
- 標準テンプレートから Twig に移すときは、同じブログに同じ名前の ID を二つ作れない。既存の ID のモジュールを V2 のものに切り替えるか、別の名前で V2 用の ID を作る（前者は標準テンプレート側からは見つからなくなる）。
