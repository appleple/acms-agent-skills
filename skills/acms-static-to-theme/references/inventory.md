# scripts/inventory.sh の読み方

```sh
sh scripts/inventory.sh <静的サイトのディレクトリ>
```

- 静的サイトのディレクトリ（`index.html` があるディレクトリ）を渡す。ファイルは読むだけで書き換えない。外部通信はしない。
- `node_modules/` と `.git/` は読まない。
- 共通とみなす割合は既定で 80%（ページが 3 以下なら全ページ）。変えるときは `INVENTORY_COMMON_RATIO=70 sh scripts/inventory.sh …`。
- HTML は「タグとタグの間で改行し、空白をまとめた形」にしてから比べる。圧縮された 1 行の HTML も、手書きの HTML も同じに扱える。出力の行番号はこの形での番号で、元のファイルの行番号ではない。

## 項目ごとの使い方

| 項目 | 使い方 | 推定を外しやすい場面 |
|---|---|---|
| ページ | 推定の役割（トップ・一覧・一覧の続き・詳細・固定ページ・フォーム）を、手順 4 の割り当て表の下書きにする | 一覧が JavaScript で描かれている、リンクが `onclick` で書かれている |
| system テーマと同じパス | `404.html`・`sitemap.xml` などをテーマに置くかを決める | ― |
| リンクの構造 | 同じディレクトリの 3 ページ以上へリンクするページのうち、件数がそのディレクトリでの最大の半分以上のものを一覧の候補、リンク先を詳細の候補にする。半分未満のものは「新着・関連記事の欄」として数だけ出す。一覧からリンクされ、一覧に無い詳細へ 2 つ以上リンクし、一覧と title が同じか、別のディレクトリ（`page/2/` など）にあるか、自分も一覧の候補であるページを「一覧の続き」とする。8 割以上のページからリンクされる先はナビゲーションとして除く | 一覧の 1 ページの件数が少ない（2 件以下）、一覧が JavaScript で描かれている、2 ページ目の title が 1 ページ目と違い同じディレクトリにある |
| 共通ブロック | トップページの中で、基準以上のページに同じ行が続く範囲。head の中・本文の前・本文の後に分けて出す。インクルードかレイアウトに分ける範囲の目安にする | ページごとに現在地の class が違うナビゲーションは、範囲が途切れて出る。トップだけ構造が違うサイトでは、下層のページを開いて確かめる |
| 繰り返し構造 | 同じタグ・同じ class の要素が 3 個以上あり、近くにリンクか画像があるもの。近くのリンク先が詳細の候補なら、エントリーの一覧にする部分 | class の無い `li` は、直前に開いた入れ物（`ul` など）と組で数える。全ページ共通の部分の繰り返しは省く |
| フォーム | action の形（空・`#`・相対・外部）、入力欄の name と type。外部に送っているフォームは利用者に確かめる | JavaScript で送っているフォーム |
| アセットの参照 | パスの形（root・relative・external）の件数、外部のホスト、見つからないファイル、ハッシュ付きのファイル名、generator、マニフェスト、ソースマップ | `data-src` などの JavaScript で読む属性、JavaScript の中のパスは数えない |
| CSS ファイルの中の url() | `/` から始まるものは、テーマに置くと外れるので直す | `@import` は数えない |
| テンプレートの記法と衝突しそうな箇所 | Twig の区切り、改行を含まない `{…}`、`<!-- BEGIN`・`<!-- END` のコメント、`%{`、`@include(` などの数。テンプレートにする前にエスケープするか書き換える | 数えるだけなので、どれがモジュールで囲む範囲に入るかは、置き換えるときに見る |
| 言語 | `html` の `lang` の値と数、hreflang の有無 | lang を書いていないサイト |

## 出力をそのまま信じない

推定は HTML の形だけから行う。役割・範囲・候補は、実際のファイルを開いて確かめてから利用者に示す。特に次の 2 つは利用者に確かめる。

- 一覧と詳細の候補のうち、どれを CMS で更新できるようにするか（手順 4）。
- 共通ブロックに入っていない差分（トップだけの見出し、ページごとの現在地）をどう出し分けるか（手順 5）。
