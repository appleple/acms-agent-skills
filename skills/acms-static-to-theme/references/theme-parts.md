# テーマに入れる共通の部品と、ファイルの分け方

手順 5 でテーマの骨組みを作るときに読む。記法の細部は acms-template-acms / acms-template-twig、読み込みの細部は acms-theme-development を読む。

## 共通部分をインクルードに分けるか

静的なまま残すページが、a-blog cms を通るかどうかで決める。

| 静的なまま残すページの置き場所 | 共通部分（ヘッダー・フッターなど） |
|---|---|
| テーマの中（URL と同じパスに置いて a-blog cms に表示させる） | インクルードかレイアウトに分けてよい。残したページもテンプレートとして処理されるので、同じ部品を読み込める |
| ドキュメントルートなど、テーマの外（a-blog cms を通らない） | 分けない。CMS 化したページだけが部品を読み、残したページは元の HTML のままになり、同じマークアップの出所が 2 つになる。片方を直すともう片方とずれる |
| まだ決まっていない（「お知らせだけ CMS 化」で、残りの扱いが未定） | 利用者に確かめる。決まるまでは分けず、元の HTML と同じ 1 ファイルで完結する形を保つ |

- ドキュメントルートに実在するファイルは、配布物の `.htaccess` の設定ではウェブサーバーがそのまま返し、a-blog cms を通らない。テーマの中のファイルは a-blog cms が表示する（テンプレートとして処理される）。
- 分けなかった場合も、どちらにしたかと理由を利用者に伝える。後から全ページを CMS 化するときに分ければよい。

## `<head>` に入れるもの

- `acms.js` は Js モジュール（標準テンプレートは `<!-- BEGIN_MODULE Js -->`、Twig は `module('V2_Js')`）で出す。管理用 CSS（`/css/acms-admin.min.css`）はログイン中だけ読み込んでもよい。書き方と理由は acms-theme-development の references/assets-and-javascript.md を読む（ここには書かない）。
- テーマを割り当てた直後は管理用 CSS が無く、次の管理ボックスの見た目が崩れる。管理ボックスと同時に入れる。

## 管理ボックス

- 標準テンプレートも Twig も、テンプレートの本文に `@include("/admin/action.html")` を書く（Twig では Twig の処理の後に `@include` が展開される。公式の Twig 版チュートリアルも同じ書き方）。
- system テーマの `admin/action.html` は、編集の権限を持つユーザーがログインしているときだけ中身を出し、プレビュー中は出さない。`Touch_Login` などで囲まなくてよい。
- CMS 化した全テンプレートの同じ位置に入れる。テーマを切り替えた時点で、元のテーマにあった管理画面への入口が消えるため、手順 5 の最初に入れる。
- エントリーの編集ボタンは、エントリーの詳細のモジュールの中に別の部品（標準は `@include("/admin/entry/action.html")`、Twig は `include('/admin/entry/action.twig', { entry })`）で入れる。どの変数を渡すかは acms-template-twig の references/rendering.md。

## エントリーの本文（ユニット）

- 本文は、system テーマの `include/unit.html` で表示する（中身は `_layouts/unit.html` を `@extends` しているだけ）。テーマに同じパスのファイルを置かなければ system のものが使われるので、見た目を変えないなら作らなくてよい。
- 見た目を変えるなら、テーマに `include/unit.html` を置き、`@extends("/_layouts/unit.html")` のうえで、変えたい種類の `@section(…)` だけを書き直す。セクションの名前は system テーマの `_layouts/unit.html` で確かめる（`text-unit`・`image-unit`・`media-unit` など）。
- **画像を入れるユニットが「画像」か「メディア」かは、ブログの設定（編集画面セット、または編集設定のユニットメニュー）で決まる。** メニューにメディアだけがあるなら、編集者が入れる画像はメディアユニットになり、`image-unit` を書き直しても効かない。先に利用者にユニットメニューを確かめてもらう。分からなければ両方を書き直す。
- **Twig でも同じ。** V2 のエントリー本文のモジュールが返す本文の HTML は、テーマの `include/unit.html` を標準テンプレートとして処理して作られる。Twig のテーマでも、ユニットの見た目は標準テンプレートの `include/unit.html` で変える。

## カテゴリー別のテンプレートと、テーマ直下の一覧・詳細

- カテゴリー別のテンプレート（`news/index.html`・`news/_entry.html`）は、URL にそのカテゴリーがあるページでだけ使われる。
- **カテゴリーを含まない URL（タグ・日付・キーワード検索の一覧など）では、テーマ直下の `tpl_index`（既定 `index.html`）が使われ、無ければ 404 になる。** カテゴリーに入れていないエントリーの詳細も、テーマ直下の `tpl_detail`（既定 `_entry.html`）を使う。system テーマにはこれらのファイルが無いため、テーマに置かなければ 404 になる。
- 静的サイトのトップの `index.html` を `_top.html` に変えた後、テーマ直下に一覧用の `index.html` が無くなっていないかを確かめる。タグ・日付の一覧を使わないなら、利用者にそう決めてもらったうえで置かないことを選んでよい。使うなら、一覧の部分を部品に分けてカテゴリー別の一覧とテーマ直下の `index.html` の両方から読み込む。そのとき、使うモジュール ID がカテゴリーを固定していないか（タグ・日付の一覧でもお知らせしか出ない、にならないか）を確かめる。
- 探す順番の全体は acms-theme-development の references/template-resolution.md を読む。
