# 置き換えた後の確かめ方

手順 6 の各回の後と、手順 8 で読む。上から順に、安く確かめられるものから進める。

## 0. キャッシュを先に疑わない・自分で消さない

- テンプレートを直しても表示が変わらないときは、テンプレートキャッシュ・ページキャッシュ・モジュール ID のキャッシュが残っていることがある。モジュール ID の設定やブロック名を疑う前に、キャッシュのクリアを利用者に頼む。
- 頼み方: 管理画面のダッシュボードの「キャッシュクリア」で、「ページ キャッシュ」「テンプレート キャッシュ」（モジュール ID のキャッシュを使っていれば「モジュール キャッシュ」も）にチェックしてクリアする。
- **エージェントはキャッシュのファイルや DB の行を直接消さない。** 設定・データと同じ場所にあり、消し方を誤ると復旧に手間がかかるため。管理画面の操作として利用者に頼む。
- デバッグモードのユーザーでログインしていれば、Twig のテンプレートは更新が検知される（acms-template-twig）。

## 1. 開始と終了の対応（標準テンプレート）

```sh
sh scripts/check-blocks.sh themes/<テーマ名>
```

- `BEGIN_MODULE`/`END_MODULE`、`BEGIN 名前`/`END 名前`、`BEGIN_IF`/`ELSE_IF`/`ELSE`/`END_IF` の対応をファイルごとに確かめる。閉じ忘れ・名前の綴りの食い違い・`ELSEIF` のような本体が読まない綴り・静的 HTML に残った `<!-- END 名前 -->` 形式の目印が出る。
- 終了コードは 0（食い違いなし）・1（あり）・2（使い方の誤り）。ファイルは書き換えない。
- 1 つのブロックを `@include` の先にまたがせていると誤検出になる。出た行は実際のファイルを開いて確かめる。
- 変数名・ブロック名の実在は確かめない（references/lookup.md の変数表で確かめる）。Twig のファイル（`.twig`）は対象外。Twig の構文の誤りは、ページを開いたときに本体がエラーにする。

## 2. 主要な URL のステータス

利用者の環境の URL で、次をすべて開く（`curl -s -o /dev/null -w '%{http_code}' <URL>` など）。

| ページ | 期待 |
|---|---|
| トップ | 200 |
| CMS 化した一覧（`/news/` など） | 200 |
| その 2 ページ目（一覧のページャーのリンク先） | 200。1 ページ目と違うエントリーが出る |
| 詳細（実在するエントリー） | 200 |
| 存在しない詳細（でたらめなファイル名） | 404 |
| タグ・日付の一覧を使うなら、その URL | 200（references/theme-parts.md の「テーマ直下の一覧・詳細」） |
| 静的なまま残したページ | 200 |
| 置き換えが済んで消した元の詳細・2 ページ目の URL | 404（古い内容が出ない） |

## 3. 出力に展開されていない記法が残っていないか

各ページの HTML を取得し、`%{` と、`{` で始まる英数字の並びを探す。

- `%{…}` が残っている: そのグローバル変数の名前が誤っている（存在しない名前は置き換えられずにそのまま出る）。
- `{title}` のような変数が残っている: モジュールの外に書いている（変数を置き換えるのはモジュール）か、`\{` でエスケープしたまま出している。
- 静的サイトのインライン JavaScript・CSS・Alpine.js などの波括弧も引っかかる。元の HTML にもあるものかを比べて区別する。
- ログインした状態とログアウトした状態の両方で取得する（ログイン中だけ出る管理用の要素があるため）。

## 4. 静的なまま残したページの差分

元のファイルと、a-blog cms を通した出力を比べる（`diff`）。次は正常な差分なので、それ以外が無いことを確かめる。

| 正常な差分 | 理由 |
|---|---|
| `</head>` の直前の `meta name="generator"` | 本体がすべての HTML に入れる |
| `</head>` の直前の `meta name="csrf-token"`、`</form>` の直前の hidden の入力欄（`formToken` など） | 本体がフォームの保護のために入れる |
| `src`・`href` などのパスがテーマの場所に書き換わっている | テンプレート内のパスの書き換え（acms-theme-development） |
| `<head>` の中に本体のアセットの読み込みが足される | ログイン中・機能によって本体が足す |

これ以外の差分（中身の一部が消えている、`{…}` が消えている）は、記法と衝突している箇所（SKILL.md の「落とし穴」）を疑う。

## 5. ブラウザでの確認

- 静的サイトと見比べる。リンク・画像・フォームの送信（入力 → 確認 → 完了 → メール）を確かめる。
- 開発者ツールのコンソールのエラーと、読み込めないファイル（404）を見る。CSS の中の `url()` と JavaScript の中のパスは本体が書き換えないので、ここで見つかることが多い。
- モジュール ID を作る前でも表示は確かめられる。その間は絞り込みが効かず、ほかのカテゴリーのエントリーが混ざることがある。利用者には「手順書のモジュール ID を作り終えるまではこう見える」と先に伝える。
