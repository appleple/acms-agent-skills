# 管理画面で利用者がする作業の一覧

手順 6 の各回と手順 7 で、利用者に渡す一覧を作るときに読む。テンプレートに書いたブログ・カテゴリー・モジュール ID・フォーム ID・テーマセットの割り当て・エントリーは DB の設定で、ファイルを置いただけでは作られない。無くてもエラーにならず、「表示されない」「絞り込みが効かない」になる。

## 渡し方

- 作るもの・入れる値・確かめ方を表にする。値はテンプレートに書いたものと 1 文字も違わないように、テンプレートから写す。
- 順番どおりに並べる（カテゴリーより先にモジュール ID の絞り込みは設定できない、など）。
- 各行に「済んだら何が見えるか」を書き、利用者が終わったことを確かめられるようにする。
- エージェントは管理画面を操作しない。本番の環境ではなおさら、利用者が実行する。

## 一覧のひな形

置き換えた部分に関係する行だけを残して渡す。

| 順 | 作業 | 画面 | 入れる値 | 済んだら見えること |
|---|---|---|---|---|
| 1 | テーマを割り当てる | テーマ設定（テーマセット）→ ブログ編集でテーマセットを選ぶ | テーマディレクトリ名: `<テーマ名>`。template.yaml を優先する設定、Twig にするなら Twig を有効に | トップが静的サイトと同じ見た目で出る。ソースの `</head>` の前に a-blog cms の generator の meta が入る |
| 2 | 開発するユーザーをデバッグモードにする | ユーザー編集の「モード」 | デバッグモード | 管理ボックスに表示中のテンプレートのパスが出る |
| 3 | 子ブログを作る（多言語など） | ブログ管理 | ブログコード: `<en など>`、テーマセット | `/en/` が開く |
| 4 | カテゴリーを作る | カテゴリー管理 | カテゴリーコード: `<静的サイトのディレクトリ名>`、名前、公開 | `/<コード>/` で一覧のテンプレートが使われる |
| 5 | エントリーを入れる（サンプル） | エントリー作成 | カテゴリー、タイトル、本文、画像のフィールド | 一覧と詳細に出る |
| 6 | モジュール ID を作る | モジュール ID 管理 | モジュール: `<テンプレートと同じモジュール名（V2_ の有無も）>`、ID: `<テンプレートの ID>`、絞り込み（カテゴリーを固定するか、URL のカテゴリー・ページ番号を受け取るか）、件数、並び順、一覧のメイン画像に使うフィールド | 表示がその条件に変わる。管理者がホバーすると編集のリンクが出る |
| 7 | モジュール ID のフィールドに値を入れる | モジュール ID の編集画面の入力欄 | メインビジュアルの画像・文言など | トップのその部分が入力した値になる |
| 8 | ブログのフィールドに値を入れる | ブログ編集の入力欄 | サイト全体の値（SNS の URL など） | ヘッダー・フッターに出る |
| 9 | フォーム ID を作る | フォーム管理 | ID: `<テンプレートの hidden の id>`、宛先、メールのテンプレートのパス、入力チェック | 入力 → 確認 → 完了と進み、メールが届く（acms-form） |
| 10 | キャッシュを消す | ダッシュボードのキャッシュクリア | テンプレートキャッシュとページキャッシュ | 本番でテンプレートの変更が出る |

- モジュール ID の「モジュール」は、テンプレートと同じ名前を選ぶ。`Entry_Summary` 用の ID は `V2_Entry_Summary` からは見つからない（acms-module-reference）。
- 一覧のページャーを使うモジュール ID は、URL のページ番号を受け取る設定（引数のページ）を有効にする。詳細ページを URL で切り替えるモジュール ID は、URL のエントリーを受け取る設定を有効にする。どの引数がどの既定値かは acms-module-reference の「URL コンテキストと ctx」を読む。
- フォーム ID・モジュール ID を子ブログから使うなら、親ブログでグローバルにするか、ブログごとに作るかを先に決める（acms-theme-development の references/large-site.md）。

## インポートで作るもの・作らないもの

設定とデータを別の環境から運ぶ機能（モジュール ID・フォーム・コンフィグ・コンフィグセット・ブログ・エントリーのエクスポートとインポート）は、どれも **a-blog cms がエクスポートしたファイル** を取り込むためのもの。

- 開発環境の管理画面で作った設定を本番に運ぶときは、それらの機能を使ってよい。どの機能が何を運び、インポートで何が消えるかは acms-theme-development の references/large-site.md の「設定とデータを運ぶ機能」を読む。
- **エージェントは、モジュール ID・コンフィグ・エントリーのインポート用のファイル（YAML・zip）を一から作らない。** これらはテーブルの行をほぼそのまま書いた形式で、取り込むときの検証は ID の付け替えなど一部に限られる。列の過不足や値の誤りが、取り込んだ後の不具合として現れるため。
- 記事の一括の取り込み（CSV ファイルからのインポート）を使うかどうかは、references/site-types.md の「既存の記事の移行」を読む。
