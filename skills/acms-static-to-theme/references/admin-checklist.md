# 管理画面で利用者がする作業の一覧

手順 6 の各回と手順 7 で、利用者に渡す一覧を作るときに読む。テンプレートに書いたブログ・カテゴリー・モジュール ID・フォーム ID・テーマセットの割り当て・エントリーは DB の設定で、ファイルを置いただけでは作られない。無くてもエラーにならず、「表示されない」「絞り込みが効かない」になる。

## 渡し方

- 作るもの・入れる値・確かめ方を表にする。値はテンプレートに書いたものと 1 文字も違わないように、テンプレートから写す。
- 順番どおりに並べる（カテゴリーより先にモジュール ID の絞り込みは設定できない、など）。
- 各行に「済んだら何が見えるか」を書き、利用者が終わったことを確かめられるようにする。
- エージェントは管理画面を操作しない。本番の環境ではなおさら、利用者が実行する。

## 一覧のひな形

置き換えた部分に関係する行だけを残して渡す。

| 順 | 作業 | 画面 | 入れる値 | 済んだら見えること |
|---|---|---|---|---|
| 1 | テーマを割り当てる | テーマ設定（テーマセット）→ ブログ編集でテーマセットを選ぶ | テーマディレクトリ名: `<テーマ名>`。template.yaml を優先する設定、Twig にするなら Twig を有効に | トップが静的サイトと同じ見た目で出る。ソースの `</head>` の前に a-blog cms の generator の meta が入る |
| 2 | 開発するユーザーをデバッグモードにする | ユーザー編集の「モード」 | デバッグモード | 管理ボックスに表示中のテンプレートのパスが出る |
| 3 | 子ブログを作る（多言語など） | ブログ管理 | ブログコード: `<en など>`、テーマセット | `/en/` が開く |
| 4 | カテゴリーを作る | カテゴリー管理 | カテゴリーコード: `<静的サイトのディレクトリ名>`、名前、公開 | `/<コード>/` で一覧のテンプレートが使われる |
| 5 | エントリーを入れる（サンプル） | エントリー作成 | カテゴリー、タイトル、本文、画像のフィールド | 一覧と詳細に出る |
| 6 | モジュール ID を作る | モジュールID管理 | 下の「モジュール ID の設定手順書」の形で 1 つずつ書く | 表示がその条件に変わる。管理者がホバーすると編集のリンクが出る |
| 7 | モジュール ID のフィールドに値を入れる | モジュール ID の編集画面の入力欄 | メインビジュアルの画像・文言など | トップのその部分が入力した値になる |
| 8 | ブログのフィールドに値を入れる | ブログ編集の入力欄 | サイト全体の値（SNS の URL など） | ヘッダー・フッターに出る |
| 9 | フォーム ID を作る | フォーム管理 | ID: `<テンプレートの hidden の id>`、宛先、メールのテンプレートのパス、入力チェック | 入力 → 確認 → 完了と進み、メールが届く（acms-form） |
| 10 | キャッシュを消す | ダッシュボードの「キャッシュクリア」 | 「ページ キャッシュ」「テンプレート キャッシュ」（モジュール ID のキャッシュを使うなら「モジュール キャッシュ」も） | テンプレートの変更が表示に出る |

- モジュール ID の「モジュール」は、テンプレートと同じ名前を選ぶ。`Entry_Summary` 用の ID は `V2_Entry_Summary` からは見つからない（acms-module-reference）。
- フォーム ID・モジュール ID を子ブログから使うなら、親ブログでグローバルにするか、ブログごとに作るかを先に決める（acms-theme-development の references/large-site.md）。

## モジュール ID の設定手順書

テンプレートに書いたモジュール ID ごとに、利用者が管理画面でそのまま入力できる手順書を作る。エージェントが DB に書き込んだり、インポート用のファイルを作ったりはしない（下の「インポートで作るもの・作らないもの」）。

### 画面の表記をそのまま使う

項目の名前は推測せず、設置ディレクトリの次のファイルから写す（references/lookup.md）。手順書の言葉と画面の言葉が違うと、利用者が項目を探せない。

| 手順書に書くもの | 写す元 | 例 |
|---|---|---|
| モジュールの選択肢 | `themes/system/admin/module/select.html` | 「サマリー ( Entry_Summary )」「エントリー本文 ( Entry_Body )」「トピックパス ( Topicpath )」。Twig 用は「V2_サマリー ( V2_Entry_Summary )」など |
| 条件設定のタブの項目 | `themes/system/include/module/edit.html` | 「モジュールID」「名前」、引数の「カテゴリーID（cid）」と「CIDのURLコンテキストを優先する」、「エントリーID（eid）」、「ページ（page）」と「ページャーのURLコンテキストを優先する」、階層の「カテゴリー」の「下階層のカテゴリーも含める ( descendant-or-self )」 |
| 表示設定のタブの項目 | `themes/system/admin/config/` の下の `*_body.html`（V2 は `admin/config/v2/` の下） | 見出し（`<h3>`）と項目名（`<th>`）。選択肢は `<option>` の表記（「日時 ( 降順 )」など） |

- 1 つのモジュール ID ごとに「モジュール・モジュールID・名前・条件設定・表示設定・どのテンプレートで使うか」をまとめる。表示設定は、テンプレートの出力に関わる項目だけを書く。既定のままでよい項目まで並べると、利用者が要点を見落とす。
- 値はテンプレートから写す（ID の綴り、ページャーの件数など）。

### 一覧と詳細で、絞り込みの指定が違う

| 項目 | 一覧（Entry_Summary など） | 詳細（Entry_Body） |
|---|---|---|
| カテゴリーID（cid） | トップなど URL にカテゴリーが無い場所では、カテゴリーを直接指定する。カテゴリーの一覧のページでは「CIDのURLコンテキストを優先する」にチェック | 「CIDのURLコンテキストを優先する」にチェック |
| エントリーID（eid） | 指定しない | 「EIDのURLコンテキストを優先する」にチェック。無いと、表示するエントリーを URL から受け取らず、開いた記事と違う内容になる |
| ページ（page） | ページャーを使うなら「ページャーのURLコンテキストを優先する」にチェック。無いと 2 ページ目も 1 ページ目と同じ内容になる | 指定しない |
| 階層 > カテゴリー | 子カテゴリーのエントリーも出すなら「下階層のカテゴリーも含める ( descendant-or-self )」 | ― |

一覧は「どこの一覧か」をモジュール ID が決め、詳細は URL のエントリーに従う、と覚える。モジュール ID が URL より優先される仕組みは acms-module-reference の references/module-id.md の「URL コンテキストと ctx の優先関係」を読む。

### 表示設定: テンプレートで使う変数に要る項目

表示設定で項目を有効にしないと、テンプレートに変数を書いても空になる。**同じ意味の項目でも、Entry_Summary と Entry_Body でキーの名前の作り方が違う**ので、一方から推測しない（V2 モジュールも同じキーを使う）。

| テンプレートで使うもの | Entry_Summary（項目 / キー） | Entry_Body（項目 / キー） |
|---|---|---|
| 日付 | エントリー日付 / `entry_summary_base_date` | エントリー日付 / `entry_body_date_on` |
| タグ | タグ / `entry_summary_tag` | タグ / `entry_body_tag_on` |
| 本文の抜粋 | サマリー / `entry_summary_fulltext` | サマリー / `entry_body_summary_on` |
| カテゴリー名（`category:veil` の中） | カテゴリー情報 / `entry_summary_category_on` | カテゴリー情報 / `entry_body_category_info_on` |
| カテゴリーのフィールド（`categoryField` の中） | カテゴリーフィールド / `entry_summary_category_field_on` | カテゴリーフィールド / `entry_body_category_field_on` |
| メイン画像 | メインイメージ / `entry_summary_image_on`。画像をユニットから取るかカスタムフィールドから取るかは「メインイメージ対象」 / `entry_summary_main_image_target` | メインイメージ / `entry_body_image_on` |
| ページャー | ページャー / `entry_summary_pager_on`（条件設定のページのチェックも要る） | ― |

- 並び順（表示順 / `entry_summary_order`）の値は `datetime-desc`（日時 ( 降順 )）・`datetime-asc`・`id-desc`・`random` など。`date-desc` のような値は無い。全部の値は `admin/config/entry/summary_body.html` の `<option>` で確かめる。
- 「バッジ（カテゴリー名）が出ない」「日付が出ない」と言われたら、テンプレートより先にこの表の項目を確かめてもらう。

### パンくず（Topicpath）

- モジュール ID を付けないと、URL のカテゴリーとエントリーに従って動く。モジュール ID を付けたときは、その ID の条件設定で次を有効にしないと、階層や記事のタイトルが出ない（ID の引数のチェックがモジュールの既定より優先されるため）。
  - 引数の「カテゴリーID（cid）」の「CIDのURLコンテキストを優先する」と、「エントリーID（eid）」の「EIDのURLコンテキストを優先する」にチェック。
  - 階層の「カテゴリー」を「下階層のカテゴリーも含める ( descendant-or-self )」に（親カテゴリーまで辿るため。「含めない ( self )」では今のカテゴリーだけになる）。
  - 表示設定の「エントリー」で「エントリーのタイトルを階層に表示する」にチェック。
- 先頭をブログ名でなく「HOME」などにしたいときは、表示設定の「起点の代替ラベル」に入れる。テンプレートでは変えられない。
- 子ブログがあるサイトの設定は公式の説明（<https://developer.a-blogcms.jp/document/topicpath/entry-2724.html>）を案内する。

### 既にあるモジュール ID を先に確かめてもらう

- 公式テーマのサンプルデータを入れた環境には、汎用の名前のモジュール ID が既にあることがある。同じブログで同じ ID は作れない（保存時に「モジュールIDが重複しています」になる）。手順書は「新しく作るもの」と「既にあるものを確かめるだけのもの」に分け、利用者にモジュールID管理の一覧を見てもらう。
- **推奨: URL コンテキストだけで内容が決まるもの（パンくず、どのカテゴリーでも同じ設定の詳細など）は、カテゴリーごとに分けず 1 つの ID を使い回す。** モジュール ID はモジュール名と ID の組で探され、置いた場所には結び付かないので、どのテンプレートからも同じ設定で使える。カテゴリーを足しても ID を増やさずに済む。ただし、こうした ID にはモジュール ID のキャッシュを設定しない（キャッシュは URL を区別しないため。acms-module-reference の references/module-id.md）。
- カテゴリーや件数など、対象によって条件が違うもの（トップのお知らせの一覧など）は、対象ごとに別の ID にする。

## インポートで作るもの・作らないもの

設定とデータを別の環境から運ぶ機能（モジュール ID・フォーム・コンフィグ・コンフィグセット・ブログ・エントリーのエクスポートとインポート）は、どれも **a-blog cms がエクスポートしたファイル** を取り込むためのもの。

- 開発環境の管理画面で作った設定を本番に運ぶときは、それらの機能を使ってよい。どの機能が何を運び、インポートで何が消えるかは acms-theme-development の references/large-site.md の「設定とデータを運ぶ機能」を読む。
- **エージェントは、モジュール ID・コンフィグ・エントリーのインポート用のファイル（YAML・zip）を一から作らない。** これらはテーブルの行をほぼそのまま書いた形式で、取り込むときの検証は ID の付け替えなど一部に限られる。列の過不足や値の誤りが、取り込んだ後の不具合として現れるため。
- 記事の一括の取り込み（CSV ファイルからのインポート）を使うかどうかは、references/site-types.md の「既存の記事の移行」を読む。
