# 静的サイトの種類ごとの判断

手順 3 で scripts/inventory.sh の出力を読んだ後、テーマへの分け方とアセットの扱いを決めるときに読む。静的サイトはどれも違うので、当てはまる行をすべて組み合わせる。

## サイトの作り方で変わること

| 作り方 | 見分け方（inventory.sh の出力） | テーマへの分け方 | アセット |
|---|---|---|---|
| 手書きの HTML（ページごとに完全な HTML） | 共通ブロックの候補が出る。ハッシュ付きのファイル名が無い | 一式をコピーして表示を確かめてから、共通ブロックをレイアウトかインクルードに分ける | 相対パスなら、部品に分ける前に `/` から始まるテーマ直下からのパスにそろえる |
| ビルドツール（Vite・webpack など）の成果物で、ソースがある | ハッシュ付きのファイル名、`type="module"`、マニフェストらしいファイル | 利用者にソースの場所を聞く。HTML はソースの HTML（または成果物）を a-blog cms のテンプレートにし、以後はテンプレートを正とする。JavaScript・CSS は引き続きビルドし、出力先をテーマの中にする | ソース・`node_modules/` はテーマの外に置く（テーマのディレクトリは Web から見える）。ファイル名にハッシュが付くなら、Vite は `@vite()` / `vite()` で読む（下の「ビルドの成果物」） |
| ビルドの成果物だけがあり、ソースが無い | 同上 | 手書きの HTML と同じに扱う。成果物の JavaScript・CSS はそのままテーマに置く（以後ビルドしないので名前は変わらない） | 圧縮された JavaScript・CSS の中のパスは書き換わらない（下の表） |
| 静的サイトジェネレーター（Astro・Eleventy・Hugo など）の成果物 | `meta name="generator"`、同じ形のページが多い | ジェネレーターのテンプレートの役目を a-blog cms のテンプレートが引き継ぐ。成果物の HTML 1 枚をひな形にする | Markdown などの記事の元データは、エントリーに移す作業として利用者と別に決める |
| CSS フレームワークを CDN から読む | 外部から読み込んでいるホストに CDN が出る | 変えない | 外部の URL は書き換わらないので、そのまま動く |
| CSS フレームワークをビルドして、使っているクラスだけを残している | ビルドの成果物の CSS が 1 つ | 同上 | a-blog cms が出す HTML（エントリーの本文のユニット、ページャー、管理用の部品）のクラスは静的 HTML に無いので、ビルドの対象にテーマのテンプレートを含め、本文は既存の本文用のスタイルの中に入れる |

## サイトの形で変わること

| サイトの形 | 見分け方 | 分け方 |
|---|---|---|
| LP（1 ページ） | ページが 1〜2、トップにページ内リンク（#）が多い、一覧と詳細の候補が無い | トップのテンプレート 1 枚で始める。インクルードへの分割は急がない。更新したいセクションごとに、モジュール ID のフィールドか 1 件のエントリーにする。完了ページはフォームのステップで出す（acms-form） |
| コーポレートサイト | 固定ページが多く、一覧はお知らせなど少数 | お知らせなどだけをエントリーにし、固定ページは静的なまま同じパスに置くところから始める。本文を運用者が直すページだけを順にエントリーにする |
| ブログ・メディア風 | 一覧と詳細の候補が大きい、カテゴリー・タグ・月別のリンク | 記事はエントリー、分類はカテゴリーとタグ。月別・タグの一覧は一覧のテンプレートを共用できる（acms-theme-development の references/template-resolution.md） |
| ページが多い（同じ形のページが数十以上） | 詳細の候補が多い | テンプレートは 1 枚のひな形から作る。記事の移行は件数が多いので、手で入れるか、利用者が a-blog cms の取り込み機能（下の「既存の記事の移行」）を使うかを決める |
| 多言語 | 言語の lang 属性が複数、言語ごとのディレクトリ、hreflang | 言語ごとに子ブログにするのが基本。ブログ名・ブログのフィールド・モジュール ID・フォーム ID を言語ごとに持て、URL も `/en/` のままにできる。共通のテンプレートは土台のテーマに置き、言語ごとの子テーマを作る（acms-theme-development） |

多言語で子ブログにするときの注意:
- 標準テンプレートでは、`/` から始まる `<a href>`・`<form action>` に表示中のブログのブログコードが補われる。共通の部品に `/about/` と書けば、英語のブログでは `/en/about/` になる。
- Twig のテーマでは、設定 `acms_anchor_no_rewrite_if_twig_enabled` が on だと、この補完が行われない（Ver. 3.2.25 以降。新規インストール時は on）。Twig で言語ごとに同じ部品を使うなら、リンクを補完に頼らずに書く（acms-theme-development の references/assets-and-javascript.md）。
- 言語間で記事をどう対応させるか（hreflang の出し方を含む）は、このスキルでは決めない。利用者と決める。

## アセット

テンプレートの中のパスは、表示のときに本体が書き換える（acms-theme-development の references/assets-and-javascript.md）。静的サイトを持ち込むときに外れやすいのは、本体が書き換えない場所。

| 場所 | 書き換え | すること |
|---|---|---|
| テンプレートの `src`・`srcset`・`<link href>`・`<style>` と `style` 属性の `url()` など | する（テーマ → 親テーマ → system の順に探して `/themes/<テーマ>/…` にする） | `/` から始まるテーマ直下からのパスにそろえると、どのテンプレートから書いても同じ結果になる |
| テンプレートの相対パス（標準テンプレート） | そのパスを書いたファイルの場所が基準 | ページをインクルードに分けると基準が変わる。分ける前に `/` から始まるパスに直す |
| テンプレートの相対パス（Twig） | インクルードした部品の中も、ページのテンプレート全体で最後にまとめて書き換える | 部品の場所は基準にならないので、`/` から始まるパスにする |
| CSS ファイルの中の `url()` | しない（ブラウザが CSS ファイルの場所から解決する） | CSS からの相対パス（`../images/x.png`）にする。`/images/x.png` はテーマの外を指して外れる |
| JavaScript ファイルの中のパス（動的 import のチャンク、`fetch`、画像のパス） | しない | ビルドツールの公開パス（Vite の `base` など）をテーマの公開場所に合わせるか、相対にする |
| ドキュメントルートや a-blog cms の設置ディレクトリに同じパスのファイルがある | そちらが優先される | テーマのファイルに、本体と重なる名前を使わない |

### ビルドの成果物

- Vite でビルドを続けるなら、Vite 連携（<https://developer.a-blogcms.jp/document/vite.html>）を使う。標準テンプレートは `@vite('…')`、Twig は `{{ vite('…') }}` で、マニフェストからハッシュ付きのファイル名を読んで `script`・`link` を出す。マニフェストはテーマの中の出力先（既定は `dist/`）から探される。開発サーバーと本番の切り替えは a-blog cms の設置ディレクトリの `.env` で行うので、利用者に設定を頼む（エージェントは `.env` を開かない）。
- Vite 以外のビルドツールでハッシュ付きの名前になるなら、ビルドの設定で名前を固定するか、テンプレートの読み込みのタグをビルドのたびに直す運用にするかを利用者と決める。
- ソースマップ（`.map`）を公開しないなら、テーマにコピーしない。

### 静的サイトの画像のうち、記事の中身だったもの

一覧・詳細の記事に使っていた画像（記事のサムネイル・本文の写真）は、CMS 化した後はエントリーの画像として管理画面からアップロードされる。テーマに残すのは、デザインの一部の画像（ロゴ・アイコン・背景）だけでよい。サンプルの記事を入れるときに使うなら、利用者に渡す。

## 既存の記事の移行

静的サイトの記事を a-blog cms のエントリーに移す手段は、a-blog cms の管理画面にある。どれを使うかは利用者が決め、利用者が実行する。

| 手段 | 向いている場面 | ドキュメント |
|---|---|---|
| 管理画面で 1 件ずつ入力する | 件数が少ない。サンプルとして数件あればよい | ― |
| CSV ファイルからのインポート | 件数が多く、タイトル・日付・本文・カスタムフィールドを表にできる | <https://developer.a-blogcms.jp/document/datamanagement/csv_convert.html> |
| エントリーのエクスポート・インポート | 別の a-blog cms の環境（開発環境など）で作ったエントリーを移す | <https://developer.a-blogcms.jp/document/datamanagement/entry-export-import.html> |

エージェントは、これらのインポート用のファイルを作って「そのまま取り込める」とは伝えない。CSV の列の形はドキュメントで利用者と確かめ、取り込む前にドライラン（使えるバージョンはドキュメントで確かめる）か少数の行で試してもらう。エントリーのインポートはカテゴリーを作らない（同じカテゴリーコードのカテゴリーが無いと「カテゴリーなし」で入る）ので、先にカテゴリーを作ってもらう。
