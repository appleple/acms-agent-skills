# 静的サイトを a-blog cms のテーマにする

このスキルは作業の順序と判断だけを持つ。記法・機能の細部は担当のスキルを読んで書く。どの静的サイトでも、下の 8 つの手順をこの順で進め、飛ばさない。

公式ドキュメント:
- チュートリアル（静的 HTML からテーマを作る。標準テンプレート版・Twig 版）: <https://developer.a-blogcms.jp/document/tutorial/>
- テーマ: <https://developer.a-blogcms.jp/document/themes/>
- Vite 連携: <https://developer.a-blogcms.jp/document/vite.html>

## 担当のスキル

| 作業 | スキル |
|---|---|
| 版・既存テーマ・標準か Twig かの判定 | acms-project-triage |
| テーマの置き場所・継承・テーマセット・パスの書き換え・デバッグモード | acms-theme-development |
| 標準テンプレートの記法（BEGIN_MODULE、@include、校正オプション） | acms-template-acms |
| Twig の記法（module()、include、エスケープ） | acms-template-twig |
| 表示したいものに合うモジュールとモジュール ID | acms-module-reference |
| お問い合わせフォーム | acms-form |
| ブログ・カテゴリー・エントリー・モジュールの入力欄（カスタムフィールド） | acms-custom-field |

## 手順

### 1. 設置環境と版を確かめる

acms-project-triage の `scripts/detect.sh` で、版・既存のテーマ・プラグイン（拡張アプリ）を確かめて利用者に伝える。a-blog cms がまだ無いなら、インストールを利用者に頼む（チュートリアルの「動作環境を用意します」）。どのブログにテーマを割り当てるか（ルートブログか子ブログか）も利用者に確かめる。

### 2. 標準テンプレートか Twig かを決める

| 状況 | 選ぶもの |
|---|---|
| 既存のテーマを親にする・既存のサイトに足す | 親・既存に合わせる |
| 新しく作り、ループや条件分岐が多い、Twig を読める人が保守する | Twig（V2 モジュールを `module()` で呼ぶ） |
| 新しく作り、HTML にタグを足す書き方で保守したい | 標準テンプレート |
| HTML に Vue などの `{{ }}` が多い | どちらでもエスケープが要る（下の「落とし穴」）。量を見て決める |

どちらでも、管理画面の入力欄のファイル（`admin/entry/field.html` など）は標準テンプレートで書く（acms-custom-field）。決めたら利用者に伝え、以降の記法は担当のスキルに従う。

### 3. 静的サイトを調べる

```sh
sh scripts/inventory.sh <静的サイトのディレクトリ>
```

ページ・共通ブロック・リンクの構造（一覧と詳細の候補）・繰り返し構造・フォーム・アセットのパスの形・CSS の中の url()・記法と衝突しそうな箇所・言語を Markdown で出す。読み方と限界は references/inventory.md を読む。出力は推定なので、候補ごとに実際のファイルを開いて確かめる。サイトの種類（ビルドの成果物、LP、多言語など）で分け方が変わるので、references/site-types.md の判断表に当てはめる。

### 4. ページと要素を a-blog cms の機能に割り当てる

references/mapping.md の対応表で、ページ（トップ・一覧・詳細・固定ページ・フォーム）と要素（サイト名、ナビゲーション、お知らせ、メインビジュアル、SNS のリンクなど）を、ブログ・カテゴリー・エントリー・モジュール・フィールド・フォームに割り当てる。割り当て表を利用者に見せ、どこを CMS で更新できるようにするか合意してから手順 5 に進む。全部を CMS 化する必要はない。更新しない部分は静的なまま残してよい。

### 5. テーマを作る

1. 静的サイト一式を `themes/<テーマ名>/` にコピーし、トップの `index.html` を `tpl_top` の名前（既定は `_top.html`）に変える。Twig にするならテーマの `template.yaml` に `tpl_twig: enabled` を書く（ファイル名と探索順は acms-template-twig）。この時点で、見た目が静的サイトと同じに出ることを確かめる（ページのソースの `</head>` の直前に a-blog cms の `meta name="generator"` が入っていれば、a-blog cms を通っている）。
2. 管理ボックス（`/admin/action.html` のインクルード）と、管理用の CSS・Js モジュールを `<head>` に入れる（チュートリアルの「管理用ボックスの設置」、読み込み方は acms-theme-development）。テーマを切り替えると管理画面への入口が消えるため、最初に入れる。
3. アセットのパスを整える。手順 3 の出力で次を直す（詳細は references/site-types.md の「アセット」）。
   - CSS ファイルの中の `/` から始まる url()（a-blog cms は CSS ファイルの中を書き換えない）。
   - 部品に切り出す予定の HTML の相対パス（標準テンプレートでは、そのパスを書いたファイルの場所が基準になる）。`/` から始まるテーマ直下からのパスにそろえる。
   - ハッシュ付きのファイル名・ビルドの成果物の置き場所。
4. 全ページに共通するブロックを、レイアウト（標準は `@extends`、Twig は `extends`）かインクルードに分ける。ページごとに違う部分（title、現在地の印、トップだけの見出し）は、グローバル変数かタッチモジュール（`Touch_Top` など）で出し分ける。
5. ページの種類ごとのテンプレートを置く。一覧はカテゴリーのディレクトリの `tpl_index`（既定 `index.html`）、詳細は `tpl_detail`（既定 `_entry.html`）。静的な詳細ページ 1 枚をひな形にして `_entry.html` を作る。置き方は acms-theme-development の references/template-resolution.md。

### 6. 動的な部分を 1 か所ずつ置き換える

一度に全部を置き換えない。1 か所ごとに「置き換える → 管理画面での作業を利用者に頼む → 表示を確かめる」を終えてから次に進む。表示が崩れたときに原因を 1 か所に絞れるため。

推奨の順序（題材によらない）:
1. 更新の多い一覧（お知らせ・ブログなど）をトップに出す部分。エントリーの一覧のモジュールに、元の繰り返しの HTML を 1 件分だけ残して入れ、値を変数に替える。
2. その詳細ページ（本文・日付・カテゴリー・タグ、`<title>` とパンくずのグローバル変数）。
3. その一覧ページ（サムネイル・ページャー）。
4. フォーム（acms-form）。
5. サイト名・連絡先・SNS などのサイト全体の値（ブログの名前とブログのフィールド）。
6. トップのメインビジュアルなど 1 か所だけの要素（モジュール ID のフィールド）。

モジュールを置くたびに、モジュール ID を付けるか決め、付けたら管理画面で作る必要があることを利用者に伝える（acms-module-reference）。置き換えが済んだ静的な詳細ページ・2 ページ目以降のファイルはテーマから消す（下の「落とし穴」）。

### 7. 管理画面で利用者がする作業の一覧を渡す

テンプレートに書いただけでは、ブログ・カテゴリー・モジュール ID・フォーム ID・テーマセットの割り当て・エントリーは作られない（DB の設定）。手順 6 の各回と最後に、references/admin-checklist.md の形で、作るもの・値・確かめ方の一覧を利用者に渡す。エージェントは管理画面を操作しない。

### 8. 確認する

- デバッグモードのユーザーでログインし、各ページで使われているテンプレートとインクルードを確かめる（acms-theme-development の「使われているテンプレートを調べる」）。
- ログアウトした状態でも見る（ログイン中は管理用の JavaScript が入り、直接表示の制限も一部外れるため）。
- 手順 3 のページ一覧を全部開き、静的サイトと見比べる。リンク・画像・フォームの送信（入力 → 確認 → 完了 → メール）を確かめる。
- 本番に置いたら、テンプレートキャッシュとページキャッシュを消してから確かめる（acms-theme-development）。

## 落とし穴（a-blog cms に静的 HTML を持ち込むとき）

- **標準テンプレートで、モジュールで囲んだ範囲の中の `{…}` は変数として扱われ、値が無ければ消える**（改行を含まない波括弧すべて）。Alpine.js の `x-data="{ open: false }"`・`:class="{ … }"`、Vue などの `{{ }}`、インラインの JavaScript・CSS の波括弧が該当する。`\{` `\}` とエスケープするか、モジュールの外に出す。
- **標準テンプレートで、モジュールの中の `<!-- BEGIN 名前 -->` 〜 `<!-- END 名前 -->` のコメントはブロックとして扱われ、中身ごと消える。** 静的 HTML の目印のコメントを、この形でない書き方に変える。
- **Twig では `{{` `{%` `{#` が構文として読まれる。** 圧縮したインラインの CSS（`{#id{…}}` のような ID セレクター）や JavaScript にあると構文エラーになる。`{% verbatim %}` で囲むか外部ファイルに出す（acms-template-twig）。
- **CSS ファイルの中の url() は書き換わらない。** テンプレートの中のパスは本体がテーマの場所に書き換えるが、外部 CSS の中はブラウザが CSS ファイルの場所から解決する。`/images/…` のような書き方は相対パスに直す。
- **テーマに残した HTML は、URL とファイル名が一致すると表示される。** CMS 化した後に元の詳細ページ（`news/2025xxxx.html` など）や 2 ページ目のファイルを残すと、古い内容が URL から開けてしまう。置き換えが済んだら消す。逆に、更新しない固定ページは同じパスに置くだけで表示できる。
- **system テーマと同じパスのファイルは、そちらを置き換える。** 静的サイトの `404.html`・`sitemap.xml` などをテーマに置くと、本体のエラーページやサイトマップの代わりに表示される。本体のものを使うなら消す。
- **名前が `_` で始まるファイルは URL から直接開けない**（新規インストール時の設定）。部品にはこれを使い、URL で開くページには使わない。
- テンプレートにモジュール ID・フォーム ID を書いても、管理画面で作るまで設定は無い。エラーにならないので気付きにくい（手順 7）。

## 守ること

- 手順 4 の割り当てを利用者と決める前に、テンプレートを書き換え始めない。
- 記法・モジュール名・変数名を推測で書かない。担当のスキルとそこから辿る変数表で確かめる。
- 管理画面の操作（モジュール ID・フォーム ID・カテゴリーの作成、テーマセットの割り当て、エントリーの投入）は利用者に頼む。インポート用のファイル（モジュール ID・コンフィグ・エントリーの YAML や CSV）を推測で作らない（本体が受け付ける形かを確かめる手段が無いため。references/admin-checklist.md）。
- `config.server.php`・`.env`・`private/` は開かない。a-blog cms の設置ディレクトリを grep や find で調べるときも、これらを対象から外す（例: `grep -rn 'tpl_twig' themes/`。設置ディレクトリ全体に grep をかけない）。設定の値が知りたければ、管理画面で確かめてもらう。
- 公式チュートリアルの題材を渡されたときの当てはめ方は references/tutorial-example.md を読む。
