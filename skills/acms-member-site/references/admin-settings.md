# 利用者に依頼する管理画面の設定

会員制サイトに必要な設定の一覧。エージェントは管理画面の設定を変えず、どの画面のどの項目をどうしてほしいかを利用者に伝える。設定はブログごと（またはコンフィグセット）なので、会員の画面を置くブログで設定してもらう。

## 管理画面 > コンフィグ > ログイン設定

| 項目 | 既定 | 会員制サイトでの扱い |
|---|---|---|
| 基本設定 > 一般サインイン機能 | 有効 | 有効のまま。無効だとサインイン・会員登録・パスワード再設定の画面は 404 |
| 基本設定 > 一般サインイン権限 | 読者 | 投稿者も会員として一般サインインさせるときだけ投稿者にする |
| 基本設定 > ログインページの指定 | 一般サインイン画面 | シークレットのブログ・カテゴリーに未ログインで来たときの行き先。会員制サイトは一般サインイン画面 |
| 基本設定 > 現在のURLでログイン / ログイン後ページの指定 | 現在のURLでログイン | ログイン後の移動先（references/templates.md） |
| 基本設定 > ログアウト後ページの指定 | トップページ | 好みで |
| 基本設定 > ログイン禁止 / ログイン画面固定 | 無効 | 子ブログのある構成で、認証の画面を特定のブログに限るとき（Ver. 3.2.20 以降） |
| メール認証サインイン > メール認証でのサインイン | 無効 | 有効にするとパスワードを使わず、メールのリンクか確認コードでサインインする。会員登録でもパスワードの欄は使われなくなる |
| セキュリティ > アカウントロック / アカウントロック時間 | 5 分間に 5 回失敗で 5 分ロック | 必要なら回数・時間を調整 |
| セキュリティ > パスワード変更の有効時間 | 15 分 | パスワード再設定メールのリンクの有効時間 |
| セキュリティ > ２段階認証 | 有効 | 会員に2段階認証を使わせないなら無効 |
| パスワードポリシー | 最小 8 文字 | 文字数・文字種・メッセージ。メッセージは画面の `{passwordPolicyMessage}` に出る |
| 会員登録機能 > ユーザー登録の外部申請 | 無効 | **有効にする**。無効だと会員登録の画面は 404 |
| 会員登録機能 > メールアドレスの有効性確認 | 確認する | 確認しない設定にすると、登録してすぐログインした状態になる |
| 会員登録機能 > 確認メールの有効時間 | 15 分 | 登録確認メールのリンクの有効時間 |
| 会員登録機能 > 権限 | 読者 | 登録される会員の権限 |
| 会員登録機能 > ステータス | 有効 | 「無効」にすると、メールアドレスの確認後も管理者が有効にするまでログインできない（承認制） |
| 会員登録機能 > どこでもログイン | 無効 | 子ブログをまたいでログインさせるとき |
| 退会機能 > 削除タイプ / データ保存期間 | 論理削除 / 90 日後 | 退会した会員の情報を残す期間 |
| SNSログイン | 無効 | Google・LINE・X でのサインイン。各サービスの ID・シークレットの入力は利用者が行う |

## 管理画面 > コンフィグ > メール設定

| 項目 | 依頼すること |
|---|---|
| 会員登録 / 会員登録（管理者） | From を自サイトのドメインのアドレスに変える（既定は `info@example.com`）。管理者宛は To を入れたときだけ送られる。テンプレートのパスを変えたときは合わせる |
| パスワード再発行 | From とテンプレート |
| メールアドレス変更 | From とテンプレート |
| メール認証サインイン | メール認証でのサインインを使うなら From とテンプレート |
| ユーザ情報変更 / ユーザー情報変更（管理者） | プロフェッショナル版以上で、会員がプロフィールを変えたときに送られる |
| SMTP サーバー | 送信できないときの確認先 |

- メールのテンプレートは、テーマの `mail/subscribe/`・`mail/reset-password/`・`mail/update-email/`・`mail/auth-signin/` などに置くと、system テーマのものより先に使われる（親子のテーマも順に探す）。
- 迷惑メール扱いを避ける考え方はメールフォームと同じ（acms-form の references/mail.md）。

## そのほか

| 画面 | 項目 | 依頼すること |
|---|---|---|
| コンフィグ > キャッシュ設定 | 読者ユーザーの場合 | 会員ごとの値をサーバー側で出すテーマなら無効のまま。有効にするなら references/security.md の条件を満たしてから |
| コンフィグ > アクセス設定 | 一般サインイン制限 | 会員がサインインできる IP アドレスを限るとき（許可外は認証の画面が 404） |
| 編集設定 > エントリー項目設定 | 会員限定 | 「表示」にしないとエントリー編集画面に「会員限定記事にする」が出ない |
| コンフィグ > Open Graph Protocol | エントリーのディスクリプションの表示設定 | 会員限定記事の本文が description に出ないようにするとき |
| テーマ設定 | テンプレート選択ファイル（template.yaml）の値を優先する | template.yaml の `tpl_*` を使うなら有効のまま |
| ブログ・カテゴリーの編集 | ステータス | 会員限定にする単位をシークレットにする（子カテゴリーも） |
| モジュール ID の設定 | 会員限定 / シークレットエントリー | 会員限定記事だけの一覧にするとき / シークレットのエントリーを未ログインの一覧に出すとき（出すと抜粋なども見える） |
| ユーザー管理 | 会員のステータス・権限・有効期限 | 承認制のときの有効化、ログインできない会員の確認 |
