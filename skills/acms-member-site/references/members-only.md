# 会員限定にする単位と、漏れる経路

会員だけに見せる範囲を決めるとき、「ログアウトしても見える」「一覧に会員限定の文が出る」と相談されたときに読む。

## 単位ごとの実現方法

| 単位 | 方法 | 未ログインで開いたとき | 備考 |
|---|---|---|---|
| ブログ全体 | ブログのステータスを「シークレット」 | サインイン画面（ログイン設定の「ログインページの指定」で管理ログイン画面にもできる）へ送られ、ログイン後に元の URL へ戻る | 子ブログを会員専用にする構成に向く |
| カテゴリー | カテゴリーのステータスを「シークレット」 | 同上 | member テーマは `mypage` をシークレットのカテゴリーにしている |
| エントリーの続き | 「会員限定記事にする」＋「続きを読む」のバー | バーより前のユニットと、会員登録・サインインへの案内が出る | ログイン中は、バーより後のユニットを組み込み JS が `ajax/members-only-content.html` から読み込んで差し込む |
| ページの一部の表示 | Touch モジュール、組み込み JS | — | 内容を隠す手段ではない（後述） |

- シークレットは「ログインしていれば誰でも見られる」。権限や会員種別で見せ分ける仕組みは標準には無い。会員限定記事の続きも、ログインしていれば権限を問わず読み込まれる。
- シークレットの判定は、表示中のブログと表示中のカテゴリー自身のステータスだけを見る。親カテゴリーをシークレットにしても、子カテゴリーのステータスが「公開」ならそのエントリーは誰でも見られる。カテゴリーの編集画面で 1 件ずつ変えたときは子に伝わらない。カテゴリー一覧の一括のステータス変更は子孫にも同じステータスを付ける。どちらの場合も、子カテゴリーのステータスを確かめる。

### 会員限定記事

- エントリー編集画面の「会員限定記事にする」は、編集画面の設定（編集設定の「エントリー項目設定」）で「会員限定」を「表示」にしないと出てこない（member テーマのセットアップデータでは表示になっている）。出てこないときは利用者に設定を依頼する。
- チェックを付けると、「続きを読む」のバーの表示が「以下のユニットが会員限定になります」に変わる。バーの位置が会員限定の境目になる。
- 詳細ページの `Entry_Body` は、ログインの有無にかかわらず、バーより前のユニットだけを出す。そのうえで、表示中のページ（マイクロページ）にバーより後のユニットがあると `continueLink` ブロックを出す。
- テンプレートには、`continueLink` ブロックの中に `class="js-members-only-entry"`・`data-eid="%{EID}"`・`data-page="%{PAGE}"`・`style="display: none;"` を持つ要素を置き、acms.js を読み込む。組み込み JS がログインを確かめ、ログイン中なら続きを差し込み、未ログインなら要素を表示する（中に会員登録・サインインの案内を書いておく）。手本は member テーマの `include/parts/members-only.html`（system テーマにも `include/members-only.html` がある）。
- 「サインインして続きを読む」ボタンは `ACMS_POST_Member_SigninRedirect`（`bid` と `eid` を hidden で送る）。サインイン後にそのエントリーへ戻る。
- 会員限定の印は `Entry_Body`・`Entry_Summary` の `membersOnly` ブロックで出せる。Twig の V2 モジュールでは各エントリーの `isMembersOnly`、`V2_Entry_Body` では続きがあるかを `hasSecretUnits` で受ける。
- 会員限定記事だけを並べる一覧は、モジュール ID の設定の「会員限定」（会員限定にチェックが入ったエントリーのみ表示）を使う。
- 続きの部分のユニットの HTML は、テーマの `ajax/members-only-content.html`（無ければ system テーマ）で組み立てられる。ユニットの見た目を変えているテーマは、この中で読み込むユニットのテンプレートも同じものになっているか確かめる。

## 漏れる経路

| 経路 | 会員限定記事（バーより後） | シークレットのブログ・カテゴリー |
|---|---|---|
| 詳細ページの本文 | バーがあれば出ない。**バーが無いと全部出る** | 未ログインはサインイン画面へ |
| タイトル・エントリーのカスタムフィールド・メイン画像 | **出る** | 出ない |
| 一覧の本文の抜粋（Entry_Summary の `summary`、V2 も同じ） | **バーより後も含めた本文の先頭から作られる**。公開部分が抜粋の文字数より短いと出る | 出ない（モジュールの「シークレットエントリー」を有効にすると出る） |
| OGP・meta の description | エントリーのフィールド（既定は `entry_meta_description`）が空なら、上と同じ本文から作られる | 未ログインはページ自体を開けない |
| キーワード検索 | バーより後の文でもヒットする（検索用の本文に全ユニットが入る） | 出ない |
| RSS 2.0（Feed_Rss2） | バーがあればバーまで。**バーが無いと全部出る** | 出ない |
| サイトマップ | URL は載る | 出ない |
| Unit_List | **バーより後のユニットも並ぶ** | — |

対策:
- 会員限定記事は必ずバーを置き、公開部分にリード文を十分に書く（抜粋・description が公開部分で埋まるように）。
- description は、エントリーのフィールドに書く運用にするか、OGP の設定の「エントリーのカスタムフィールドに値が設定されていない場合はエントリーのディスクリプションを表示しない」を有効にしてもらう。
- 会員限定記事のカテゴリーで Unit_List を使わない。
- 一覧に会員限定記事を出すときは、抜粋を出さない（または文字数を短くする）テンプレートにする。
- ここに挙げた挙動は v3.2.38 のソースで確かめたもの。抜粋の文字数・検索の対象などをサイト側で変えている場合は、実際の出力で確かめる。

## ログイン状態で表示を変える方法の選び方

| 方法 | 仕組み | 使いどころ |
|---|---|---|
| `Touch_Login` / `Touch_Unlogin` | サーバーで出し分ける。プレビュー中は未ログイン扱い | ページキャッシュの「読者ユーザーの場合」が無効なら、ヘッダーのサインイン・マイページの切り替えなどに使える |
| `Touch_SessionWithSubscription` など権限の Touch | 権限で出し分ける | 読者以上・投稿者以上などで出し分けたいとき |
| 組み込み JS（`js-login-show` / `js-login-hidden` / `js-logout-show` / `js-logout-hidden`） | ページを表示した後に JavaScript でログインを確かめ、`display` を切り替える。表示するときの値は `data-display` で変えられる | 「読者ユーザーの場合」のページキャッシュを有効にしたサイト。最初は `style="display: none;"` を付けておく |
| Ajax で部品を後から読み込む（member テーマのヘッダーの名前） | `ACMS_POST_2GET_Ajax` で別テンプレートを `nocache=yes` 付きで取得する | 会員ごとの値をキャッシュされたページに出すとき |

- 組み込み JS は表示を切り替えるだけなので、HTML には常に含まれている。会員限定の内容には使わない。
- Touch モジュールの中に書いた内容も、そのページがキャッシュされる条件なら、キャッシュの共有範囲（references/security.md）に配られる。
- 組み込み JS の説明: <https://developer.a-blogcms.jp/document/reference/builtinjs/member/display-by-login.html>、Touch モジュールの一覧: <https://developer.a-blogcms.jp/document/reference/touch.html>
