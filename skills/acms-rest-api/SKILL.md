# a-blog cms の REST API（Ver. 3.3 以降）

この内容は Ver. 3.3.0-alpha.1 のソースで確かめた。公式ドキュメント（developer.a-blogcms.jp）が公開されたら、そちらを正とする。

## 最初に確かめること

1. `acms-project-triage` でバージョンを判定する。**Ver. 3.3 未満なら REST API は無い。** 3.2 で外部とデータをやり取りするなら、モジュールの JSON 出力やプラグイン（拡張アプリ）の独自の POST モジュール（acms-plugin-development）を検討する。
2. 目的で使い分ける。

| 目的 | 使うもの |
|---|---|
| 外部のシステム・バッチ・CI から読み書きする | この REST API（API トークンか OAuth） |
| Claude などの AI エージェントにサイトを操作させる | MCP サーバー（acms-mcp）。REST と同じ安全装置が効く |
| 公開サイトの画面に一覧などを出す（訪問者向けの読み取り） | テンプレートとモジュール。REST API は匿名の読み取りと CORS を提供しない |
| 管理画面の JavaScript プラグインから呼ぶ | セッション認証（`auth.session`）。`ACMS.Config.restApiBaseUrl` を使う（acms-admin-frontend-plugin） |

## 1. 有効にする

- 管理画面の「REST API 設定」で REST API を有効にする（`rest_api_enable`、既定は off）。ルートブログで設定し、ブログごとに上書きできる。off でも、管理画面からのセッション認証の呼び出しは通る。
- 同じ画面で、API を使える権限（既定は管理者・編集者・投稿者。読者は含まない）、接続元の IP、レート制限、削除などの操作の上限を決める。必要な権限・IP だけに絞る。
- URL は `https://<ドメイン>/rest-api/acms/v1/`（子ブログは `/<ブログのコード>/rest-api/acms/v1/`）。**末尾の `/` を付ける**（付けないと 301 になり、POST の本文が失われる）。
- `rest-api`・`mcp`・`oauth` は機能を有効にしていなくても予約された URL のセグメントになる。同じコードのブログ・カテゴリー・エイリアス・エントリーは 404 になり、保存もできない。既存サイトで衝突するなら、利用者にコードの変更か、`config.server.php` の `REST_API_SEGMENT` などの定数の変更を依頼する（エージェントは `config.server.php` を開かない）。
- 既存サイトの `.htaccess` はアップデートで更新されない。同梱の `htaccess.txt` との差（予約セグメントと `/.well-known/` の除外）を利用者に取り込んでもらう。OAuth を使うなら必須。

## 2. 認証する

| 方法 | 使う場面 |
|---|---|
| API トークン（アプリパスワード） | サーバー間の連携・バッチ。ユーザー編集画面の「API トークン」で発行する |
| OAuth 2.1（認可コード + PKCE） | 利用者が自分のアカウントで外部アプリをつなぐ。claude.ai などのコネクタ |
| セッション（`auth.session`） | 管理画面の JavaScript からだけ |

スコープの選び方、トークンの扱い、OAuth の設定は references/authentication.md を読む。守ること:

- トークンは `Authorization: Bearer` ヘッダーで送る（クエリ文字列では受け付けない）。HTTPS でなければ 403 になる。
- **トークンの値をチャット・コマンドライン・リポジトリに書かない。** 環境変数（例: `ACMS_API_TOKEN`）に入れてもらい、コマンドでは `"Authorization: Bearer ${ACMS_API_TOKEN}"` と変数で参照する。利用者がトークンを貼り付けたら、使わずに失効と再発行を勧める。
- スコープは必要な最小限にする。読むだけなら `entries:read` のようにリソースごとの read にし、汎用の `write` を付けない。本番用と検証用でトークンを分ける。

## 3. 仕様を確かめてから書く

エンドポイント・項目・クエリは、記憶やこのスキルから組み立てず、**対象のサイトの実物から読む**。バージョンやプラグインでルートが増減するため。

1. `GET /rest-api/acms/v1/me/` で疎通とトークンを確かめる（スコープは不要。持ち主・スコープ・このブログでの権限が返る）。
2. `GET /rest-api/acms/v1/openapi.json`（OpenAPI 3.1。プラグインのルートも載る）から、使うルートのパラメータ・リクエスト・応答の形と必要なスコープを読む。
3. 書き込みは、まず `?dry_run=1` で送り、検証のエラーが無いことを確かめてから本番の送信をする。

## 4. 安全に読み書きする

| 場面 | 決まり |
|---|---|
| 作成・更新を試す | `?dry_run=1`（応答に `Acms-Dry-Run: true`）。DB の外（ファイル・メール）は取り消せないので、メディアの登録などは検証環境で試す |
| 更新 | 単体の GET が返す `ETag` を `If-Match` に付ける（他の人の変更を上書きしない。412 なら読み直す）。PATCH は送った項目だけを変える |
| 作成の再送 | POST に `Idempotency-Key` を付ける（タイムアウト後の再送で二重に作らない） |
| 削除 | 既定はゴミ箱へ移す。物理削除の `?force=true` は、利用者が対象と復元できないことを確認してからだけ使う |
| 公開中のエントリー | 公開・非公開・公開中の更新と削除には専用のスコープ `entries:publish` が要る。持たないトークンでは、既存のエントリーの変更は新しいバージョン（`POST /entries/{id}/revisions`）として保存し、新しいエントリーは下書き・非公開で作り、公開は人が行う |
| 外部の ID（品番など）で既存のエントリーを探す | 外部の ID をカスタムフィールドに保存しておき、一覧の `field` のクエリで探す。見つかれば更新、無ければ作成にする（クエリの書き方は openapi.json で確かめる） |
| 一覧 | `limit` は 1〜100。次のページは応答の `links.next` をたどり、URL を組み立てない |
| 時間のかかる処理（バックアップ・エクスポート・インポートなど） | 202 で受け付けられる。`GET /jobs/{id}` で終わりを確かめる |
| 本番のデータを大量に変える | 先に件数と対象を利用者に示して確認を取り、少数で試してから進める。削除などの操作はトークンごとに 1 時間あたりの上限がある |

## 5. エラーを読む

- エラーは RFC 9457 の `application/problem+json`。分岐は翻訳される `title` ではなく、変わらない `code` で行う。項目の誤りは `errors[].pointer`（どの項目か）に出る。
- 未知の項目は 422 `unknown_field`、読み取り専用の項目は 422 `read_only_field` で、黙って無視されない。
- よく出るものと直し方は references/troubleshooting.md を読む。

## 6. カスタムフィールドとユニット

- `fields` は、フィールド定義（acms-field-definition）のあるキーは型どおりの JSON（数値、配列、参照先の ID、繰り返しは行の配列）で読み書きし、定義の無いキーは文字列で読み書きする。PATCH は送ったキーだけを置き換え、`null` で消す。
- 画像・ファイル（アーカイブ）の項目とユニットは読み取りだけ。画像はメディアとして登録してから、メディアの ID で参照する。
- 読み取りと書き込みで項目の名前が違うものがあるため、GET した `units` をそのまま PATCH に送らない。openapi.json の書き込み側のスキーマに合わせる。

## 7. プラグイン（拡張アプリ）から拡張する

独自のルート・スコープ・認証・コアのリソースへの項目の追加は references/plugin-routes.md を読む。足したルートは openapi.json と MCP のツールにも自動で載る。

## よくある誤り

- 3.2 のサイトで REST API を案内する。
- 末尾の `/` を付けずに POST して、本文が失われる（301）。
- MCP の URL を `/rest-api/mcp/` と書く（MCP は `/mcp/`。acms-mcp）。
- エンドポイントの形を推測で書く（openapi.json を読む）。
- トークンをコマンドや設定ファイルに直書きする。
- 汎用の `write` や `entries:publish` を必要もなく付ける。
- 公開サイトの JavaScript から REST API を呼ぼうとする（匿名の読み取りと CORS は無い。モジュールで出す）。
