# 改ざん・送信の失敗への備えと送信データ

公式: <https://developer.a-blogcms.jp/document/form/form-security.html>、<https://developer.a-blogcms.jp/document/form/data_check.html>。

## フォーム ID はどのフォームからでも送れる

- 本体は送られてきた `id` を、今のブログで作ったフォーム ID と、親のブログで「グローバル」にしたフォーム ID の中から探す。見つかればそのフォーム ID の設定（宛先・メールテンプレート・管理画面の入力チェック）で処理する。どのページのどのフォームから送られたかは見ない。
- つまり、ある画面の hidden の `id` を書き換えれば、同じブログの別のフォーム ID（関係者だけに案内している申込フォームなど）へも送れる。検証も送り先のフォーム ID の管理画面の設定しか効かない。
- そのため:
  - どのフォーム ID も「誰がどこから送ってきても困らない」設定にする。宛先は管理画面に固定し、入力チェックは管理画面に書く。
  - 「お問い合わせ種別で送り先を変える」ために `id` を入力値で切り替える作りは、利用者が任意のフォーム ID を選べることと同じになる。切り替え先がどれも公開してよいフォーム ID だと確かめたうえで採用する。宛先の hidden（`AdminTo[]`）を入力値で切り替える作りは、任意のアドレスへ送らせられるので採らない。
  - 種別ごとに受付を分けたいだけなら、フォーム ID を 1 つにして種別を項目として保存・メールに載せ、メールソフト側で振り分ける方法も検討する。

## フォーム ID が空・不正なとき

- 確認・送信のどちらでも、フォーム ID が見つからなければ処理を止め、ステップを `forbidden` にし、監査ログに「フォームID「…」が存在しないため…中断しました」を critical で記録する。
- 標準テンプレートで `step#forbidden` を書いていないと入力画面に戻るだけで、利用者は何度押しても先へ進めない。Twig で `forbidden` を受けていないと何も表示されない。
- よくある原因は、`id` を JavaScript で組み立てる作り。ブラウザの「戻る」で確認画面から入力画面に戻ると、ブラウザは select などの入力値を復元するが、JavaScript の状態（フレームワークの変数など）は初期化し直される。その結果、見た目は選択済みなのに `id` の hidden が空のまま送られる。
  - `id` は各ステップに固定値で書く。どうしても JavaScript で決めるなら、初期化時ではなく送信（submit）の瞬間にフォーム要素の実際の値から書き込む。
  - 確認画面から送信するフォームの `id` は、サーバーが出力した値（標準テンプレートの変数、Twig の `form.fields`）で書く。

## 本体にある送信時の防御

| 仕組み | 何をするか | 失敗したとき |
|---|---|---|
| CSRF トークン | `</form>` の直前に本体が `formToken` を自動で入れ、セッションの値と照合する | 確認時はシステムエラー、送信時は `forbidden` |
| 二重送信の検知 | 同じ画面から 2 回送信したことを `formUniqueToken` で検知する | `repeated` |
| 送信元の確認 | Referer が管理しているドメインでなければ受け付けない（システム設定で緩められる） | 確認時はシステムエラー、送信時は `forbidden` |
| 送信時の再検証 | 送信時にもう一度検証する。ただし takeover から戻した値ではテンプレートの `:v#` が取り除かれるので、効くのは管理画面の入力チェックだけ | 入力画面（エラー表示） |
| テンプレート指定の無効化・複数アドレスの無効化 | 宛先の hidden の書き換えを防ぐ（references/mail.md） | — |
| `duplication`（管理画面の入力チェック） | 過去に送られたメールアドレスなら失敗させる | 入力画面（エラー表示） |

- フォームのあるページを CDN などでページごとキャッシュしない。HTML に埋め込まれた CSRF トークンが別の人のセッションのものになり、送信が `forbidden` になる。
- `Referrer-Policy: no-referrer` を返すサイトでは Referer が空になり、送信が `forbidden` になる（システム設定で空の Referer を許可していない場合）。
- CAPTCHA は本体に無い。必要ならプラグイン（拡張アプリ）を使う。

## 送信データの保存と確認

- 送信データは、フォーム ID の設定で「ログを残さないようにする」にしていなければ保存される。管理画面のフォームの「投稿データ」で、自動返信・管理者宛それぞれの件名・本文を見られ、CSV でダウンロードできる。
- Ver. 3.2.37 以降は、メールの送信状態（送信済み・失敗・送信しない）が記録され、投稿データの一覧から再送できる（添付ファイルは再送されない）。
- 「ログを残さない」にすると、内容はメールにしか残らない。個人情報を DB に残したくない要件のとき以外は残す。
