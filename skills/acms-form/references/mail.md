# メールテンプレートと宛先・送信元

公式: <https://developer.a-blogcms.jp/document/form/template.html>、<https://developer.a-blogcms.jp/document/form/form_id.html>、<https://developer.a-blogcms.jp/document/form/form-security.html>。

## メールテンプレートの置き場所

- 管理画面のフォーム設定で、件名・本文のファイルをテーマのディレクトリを基準にしたパスで指定する（例: `/contact/form/subject.txt`）。自動返信（`SubjectTpl` / `BodyTpl` / `BodyHTMLTpl`）と管理者宛（`AdminSubjectTpl` / `AdminBodyTpl` / `AdminBodyHTMLTpl`）の 6 つ。
- ファイルは使用中のテーマ → 親テーマ（`@` の継承）→ `system` の順に探される。公式テーマは `contact/form/` に `subject.txt` `body.txt` `adminsubject.txt` `adminbody.txt`（HTML メールは `body.html` `adminbody.html`）を置いている。
- HTML メールにするときもテキストの本文ファイルは必要（HTML の本文ファイルが見つからなければテキストで送られる）。
- 件名・本文は管理画面に直接書くこともでき、書いた場合はファイルより優先される。
- 件名・本文・宛先のどれかが空のメールは送られない（自動返信が届かないときは、まず `To` と件名・本文ファイルのパスを確かめる）。

## 標準テンプレートで書く

```text
お名前：{name}[raw]
<!-- BEGIN tel:veil -->電話番号：{tel}[raw]
<!-- END tel:veil -->ご興味のある内容：<!-- BEGIN topics:loop --><!-- BEGIN topics:glue -->、<!-- END topics:glue -->{topics}[raw]<!-- END topics:loop -->
受付番号：{serialNumber}
```

- 入力値は `field[]` で登録した項目名の変数で出る。`{serialNumber}` はフォーム ID ごとの通し番号。グローバル変数（`%{BLOG_NAME}` など）も使える。
- 任意項目は `項目名:veil` のブロックで囲む。囲みの中の変数がすべて空なら、ラベルごと出ない。囲みの中に、常に値がある別の変数を入れない。
- 複数の値（チェックボックスなど）は `{項目名}` だと 1 つ目しか出ない。`項目名:loop` で回す。区切りの `項目名:glue` は 2 つ目以降の値の前に出るので、ループの中の **値より前** に置く。
- エスケープ: テキストメール（.txt）では既定のエスケープで `&` や `<` が文字実体参照になるため、公式テーマは入力値に `[raw]` を付けている。テキストメールは HTML として解釈されないので、ここでの `[raw]` はよい。**HTML メールでは `[raw]` を付けない**（`{inquiry}[escape|nl2br]` のようにする）。利用者が入力した HTML がそのまま管理者のメールソフトで表示されるため。

## Twig で書く（Ver. 3.2.25 以降）

- テーマで Twig が有効なら、メールテンプレートも Twig で処理される。`body.txt` を指定したときは `body.txt.twig` が先に探される。
- 入力値は `{{ name.value }}`、複数の値は `{{ topics.array|join('、') }}`。任意項目は `{% if tel.value %}...{% endif %}`。
- 自動エスケープはファイル名の拡張子で決まる（`.txt` 系はエスケープしない、`.html` 系は HTML エスケープ）。HTML メールで `|raw` を付けない。
- 管理画面に直接書いた件名・本文は、使えるタグ・フィルターを絞った環境で評価される。凝った処理はファイルに書く。

## 宛先・送信元

| 項目 | 自動返信（利用者宛） | 管理者宛 |
|---|---|---|
| 宛先 | `To` | `AdminTo` |
| 送信元 | `From` | `AdminFrom` |
| 返信先 | `Reply-To` | `AdminReply-To` |
| Cc / Bcc | `Cc` / `Bcc` | `AdminCc` / `AdminBcc` |

### 管理画面とテンプレートのどちらが使われるか

送信時に、テンプレートから送られた hidden（`To[]` など）を読み、そのあと管理画面のフォーム設定で値がある項目を上書きする。

| 管理画面の設定 | 使われる値 |
|---|---|
| 値がある | 管理画面の値（テンプレートの hidden は無視） |
| 空 | テンプレートの hidden の値 |
| 「テンプレート指定を無効」にチェック | テンプレートの hidden を捨てる。管理画面も空なら空 |

- `AdminFrom` と `AdminReply-To` が最終的に空なら、本体は `To`（自動返信の宛先＝利用者が入力したアドレス）を入れる。
- 「テンプレートでの複数アドレス指定を無効にする」にチェックすると、テンプレートからカンマ区切りで送られた宛先の先頭だけを使う。

### おすすめの設定

| 項目 | 設定 |
|---|---|
| `To` | 管理画面は空。確認画面の送信フォームに `<input type="hidden" name="To[]" value="{email}">` |
| `From` / `AdminFrom` | 管理画面に自サイトのドメインのアドレスを書き、「テンプレート指定を無効」 |
| `AdminTo` | 管理画面に受け取る人のアドレスを書き、「テンプレート指定を無効」 |
| `AdminReply-To` | 管理画面は空。`<input type="hidden" name="AdminReply-To[]" value="{email}">` |
| 使わない Cc / Bcc / Reply-To | 「テンプレート指定を無効」 |
| 複数アドレス | 「テンプレートでの複数アドレス指定を無効にする」にチェック |

理由:

- **送信元に利用者のアドレスを入れない。** メールはサイトのサーバー（または設定した SMTP サーバー）から送られる。送信元が `@gmail.com` などの利用者のドメインだと、そのドメインの SPF（送ってよいサーバーの一覧）に自サイトのサーバーが無く、DKIM の署名もそのドメインで付けられないため、DMARC の検査に失敗する。DMARC を `reject` / `quarantine` にしているドメインでは受信拒否・迷惑メール扱いになる。管理者が返信できるようにするのは `AdminReply-To` の役目。
- **宛先は管理画面に固定する。** テンプレートの hidden は利用者が書き換えられる。`AdminTo` をテンプレートに書くと、第三者が任意のアドレスへ管理者宛メールを送らせられる。`To` は利用者のアドレスを入れるためテンプレートで受けるしかないので、複数アドレスの無効化で被害を抑える。
- 公式のテーマやスニペットには `AdminFrom[]` に入力されたアドレスを入れている例がある。そのまま写さない。

## 送られないとき・届かないときの確かめ方

1. 管理画面のフォームの「投稿データ」に記録があるか。Ver. 3.2.37 以降は、ログを残す設定のフォームならメールより先に投稿データを保存し、送信状態（送信済み・失敗など）も記録する。そこから再送もできる。それより前のバージョンでは、メールの送信に失敗すると `forbidden` のステップになり、投稿データも保存されない。
2. 監査ログに、フォーム ID の不一致・CSRF・二重送信・テンプレートが見つからない旨の記録が無いか。
3. 件名・本文・宛先のどれかが空になっていないか（上の「どちらが使われるか」を見る）。
4. 迷惑メールに入るなら、送信元のドメインと送信サーバーの SPF / DKIM / DMARC を確かめる。
